# Work categories

The categories a turn of work with a coding agent can fall into. A turn is one request from the developer plus the agent's work on it. Pick the **one** category that best describes what the developer asked for. The tools the agent used are context; the request decides.

| Category | The developer wants… |
|---|---|
| `plan` | a plan, spec, scope or step list for work that has not started; deciding *what* to build or *how*, before code is written |
| `research` | to understand something: how existing code, a library or a concept works, or how options compare. No change to the code is requested |
| `implement` | new behaviour built: a feature, a new file or component, a new capability |
| `debug` | the cause of a failure, error or wrong result found and fixed |
| `test` | tests written or improved, or coverage increased, for code that already exists |
| `refactor` | the structure of existing code changed without changing what it does (extract, rename, deduplicate, move) |
| `review` | existing code or a change judged: quality, risks, readiness to ship |
| `ops` | build, CI, deployment, containers, infrastructure or developer tooling set up or changed |
| `unknown` | none of the above can be told from the request |
